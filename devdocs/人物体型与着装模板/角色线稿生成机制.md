# 角色线稿生成机制（角色无关）

> 状态：**v1 实施中**（2026-11-25）。本文件定义「结构图 → 线图」的数据契约与生成流程；
> 实现位于 `tools/tachie/lineart.py`，由 `tools/tachie/build_lsp.py build --only lineart` 调用。
> 上层管线规格见同目录 `LSP分层立绘管线.md`（§五 模块、§六 算法、§八 验收）。

## 一、目标与边界

目标：给定 **①角色基础数据**（archetype 的 body/face/hair 比例）与 **②角色描述特征**
（五官、发型、着装）以及 **③实测结构/材质数据**，自动画出该角色的**线稿**，且生成器不
含任何某一角色的硬编码数值。

- 本文件只管 **结构（不可见构造）→ 线图（可见轮廓）** 这一段；着色、高光、索引化见 LSP 管线。
- 线稿是「可见面」的第一层：`layers/30_lineart.png`（RGBA，工作分辨率 1597×2221）。
- 结构层 `90_structure.png` 为 `export:false` 的构造层，**永不出现在成品**。

## 二、体型数据分析（structure vs 底图）

数据来源：`characters/momo/lsp/half/structure.json` + 底图材质区域（检测尺度 1080，
换算系数 `factor = 2221/1080 ≈ 2.056`）。头高 `head_h = chin.y − head.top = 728.0 px`。

| 指标 | 实测值 | 头身比 | 说明 |
|---|---|---|---|
| 头高 head_h | 728.0 | 1.00h | 头顶 y=61.7，下颌 y=789.7 |
| 全高（按 heads） | 4514 | 6.20h | `proportions.heads = 6.2` |
| 脸宽（0.55h 行） | 384 | 0.53h | ≈ `face_width_ratio 0.66 × 头宽 597` |
| 眼带 | x 663–972，y 0.61–0.81h | 0.42h 宽 | 双眼中心约 735 / 900，间距 ≈0.23h |
| 肩关节跨距 | 574 | 0.79h | 关节中心，不含衣袖 |
| 衣袖外缘跨距（胸行） | 873 | 1.20h | white 区域，含短袖 |
| 腰径 | 451 | **0.620h** | 与 archetype `waist_ratio 0.62` 完全一致 |
| 盆腔宽 | 747 | 1.03h | `pelvis.ry = 193`（0.27h） |
| 躯干宽 | 674 | 0.93h | 躯干外轮廓 |
| 上臂（肩→肘） | 555–567 | 0.76–0.78h | 左右不同，允许不对称 |
| 前臂（肘→腕） | 426–440 | 0.59–0.60h | 腕点为估计段 |
| 发型外轮廓 | 宽 1533 | 2.11h | 长卷发，长度约 2.4h（检测尾部含噪声） |
| 裙摆 | 宽约 880 | 1.21h | 裙摆约 2.75h，随重心左倾 |

**结论（绘制用）**：

1. `head_h` 是全图唯一基准单位；肩、腰、盆、四肢一律用「h 倍数」表达，换角色只换基准。
2. 腰径由 `body.waist_ratio` 驱动、经实测校准后一致；面部宽度由 `face_width_ratio`
   相对**头宽**（不是头高）决定，实测 0.53h ≈ 0.66 × 597，与该字段口径吻合。
3. 发型/裙摆的**宽度远大于骨架**（2.1h / 1.2h），因此线图不能只画骨架外扩，
   必须引入**实测区域轮廓**（见 §五 C 阶段）。
4. 实测胸点位于 1.53h / 1.61h，而 archetype `bust.center_y_head = 1.9`；两者口径不同
   （模板锚点是绘制顺序用的相对锚，不是头顶起算的绝对高度）。线稿 v1 不使用该锚点，
   后续统一口径时再回填，禁止据此直接换算。

## 三、结构图与线图的关系

| | 结构图（structure） | 线图（lineart） |
|---|---|---|
| 语义 | 不可见构造：头轴/椭圆、肩线、腰圆、盆腔、关节 | 可见边界：轮廓、接缝、五官、服饰细节 |
| 数据 | `structure.json`（实测 + 估计段） | 结构 + 材质区域 + 特征描述 |
| 线条 | 辅助线（关节圆、轴线），估计段虚线 | 实线，粗细分级，无辅助线 |
| 输出 | `90_structure.png`，`export:false` | `30_lineart.png`，`export:true` |
| 变更代价 | 改 `limbs.py` 后重跑 structure | 结构变化后**必须**重跑 lineart |

**契约**：结构图回答「人体在哪、朝向、比例多少」；线图回答「哪些边可见」。
线图**不得**从结构图直接描线（会把辅助圆画进成品），而是把结构当**定位场**：
特征点（眼、纽扣、裙腰）按结构轴/关节定位，形状与边界由材质区域与特征参数决定。

## 四、角色无关的数据契约

生成器只读三类输入，任一角色只要提供这三类即可出线稿：

1. **骨架** `structure.json`：`head`（含 `axis`/`top`/`chin`/`rx`/`ry`）、`shoulder_y`、
   `waist_y`、`waist`、`pelvis`、`limbs`。字段见 LSP 管线 §四。
2. **材质区域**（角色无关的分类器产出）：`hair / skin / white / cloth / accent / eye`
   六种 role 的布尔掩码。分类规则由 `materials.json` + `matregion.classify_materials` 决定，
   与具体角色解耦。
3. **特征描述**（archetype 解析后的 `effective`）：`body`（比例/胸围）、`face`（眼型/眉型/
   鼻型/嘴型/记忆点）、`hair`（长度/前发/束发）、`outfit`（领型/配饰/图案）。

生成器禁止出现角色名、固定像素坐标或写死的颜色值；颜色取自 `palette.json` 的最深中性槽
（`_palette_ink`），线宽以 `unit = height/360` 为基准。

## 五、生成流程

```
A 测量   structure.json + 材质掩码（六 role）
B 骨架   头轴 / 肩线 / 腰圆 / 盆腔 → 特征定位场
C 轮廓   每个 role 的掩码 → Marching Squares → Chaikin 平滑 → 闭合 loop
D 特征   五官（虹膜为锚）、纽扣（躯干轴）、裙褶（裙区上下跨度）、领条（领区内缩 loop）
E 出图   分级线宽绘制到 2× 超采样 RGBA → LANCZOS 下采样 → 30_lineart.png
```

- **C 阶段是「角色无关」的关键**：轮廓来自材质分类，不来自手写模板；换角色只换掩码。
- **D 阶段是「特征描述」的落点**：五官/纽扣/裙褶/领条只依赖结构定位 + 特征参数。
- 掩码边界做 1px 内缩，避免沿裁切框描出画布边缘线。

## 六、实现要点（`tools/tachie/lineart.py`）

| 函数 | 职责 |
|---|---|
| `role_masks(idx, materials)` | 把材质索引按 role 合并为布尔掩码 |
| `trace_loops(mask, scale, min_area)` | Marching Squares 提取等值线 → 链接成闭合 loop → Chaikin 平滑；面积过小者丢弃 |
| `_offset_loop(pts, d)` | 沿局部法线向内偏移，用于领条/蝴蝶结内折线 |
| `_eye_boxes(eye_mask, scale, head)` | 以虹膜连通块为锚得到双眼中心与半径 |
| `_draw_face(...)` | 上/下眼睑、虹膜/瞳孔/高光、眉、鼻、嘴、雀斑/腮红（按 `face.markings`） |
| `_draw_garment_details(...)` | 4 颗纽扣（躯干轴）、裙腰线 + 7 条裙褶、领口双内缩条 |
| `render_lineart(...)` | 按 `hair → white → cloth → skin → accent → eye` 顺序分级描线 |
| `write_check` / `write_overlay` | 出「白底线稿」与「底图上叠加线稿」两张检查图 |

线宽分级（基准 `base = 0.46 × unit`）：

| 级别 | 倍数 | 用途 |
|---|---|---|
| 外轮廓 / 眼睑 | 1.25× / 1.05× | 整体剪影、上眼线 |
| 区域边界 | 1.0× | 发/衣/肤/领/裙边界 |
| 发丝边界 | 0.78× | 卷发分束 |
| 内部细节 | 0.38–0.62× | 裙褶、纽扣、领条、鼻、嘴 |

## 七、接口与产物

```bash
.venv/bin/python tools/tachie/build_lsp.py build --lsp characters/momo/lsp/half \
    --only lineart --detect-h 1080
```

产物：

- `characters/momo/lsp/half/layers/30_lineart.png`（线稿层，RGBA）
- `output/momo_half_lineart_check.png`（白底检查图）
- `output/momo_half_lineart_overlay.png`（底图叠加检查图，用于核对配准）
- 阶段台账：`lineart` 记录为 `pending`，**须用户确认后才可 `confirm`**。

依赖：必须先有 `structure.json`；结构层重建后线稿层 `sha256` 会变化，需重跑本层。

## 八、验收标准

1. 轮廓闭合、无画布边缘伪线、无孤立噪点 loop（面积阈值 900 px²）。
2. 眼/眉/鼻/嘴落在结构头轴与实测眼带上；两眼尺寸差 <10%。
3. 纽扣沿躯干轴、裙褶落在裙区、领条贴合领缘内缩。
4. 线稿层不含结构辅助圆/轴线；结构层仍 `export:false`。
5. 换角色不改代码：仅替换 `structure.json` + 底图掩码 + `spec/archetype` 即应出线稿。
6. `python -m unittest discover -s tools/tachie -p "test_*.py"` 全绿。

待办（按优先级）：

1. **口袋/袖口**：目前未画；需从 white 区域的局部边界测出袖口 y 与口袋框。
2. **领条几何**：现用整体内缩 loop 近似，长领角处可能偏离真实条纹走向，后续按领缘法线带绘制。
3. **发丝内线**：只描发束外轮廓，未画内部走向线；可从 hair 掩码骨架 + 特征 `hair.style` 生成。
4. **估计算法边界**：`fore_estimated` / `legs.cropped` 的结构段在线稿中不得伪装为实测，
   后续如需绘制「半成品线」应走结构层而非线稿层。
5. **多角色回归**：至少再取一个 archetype（不同头身/发型）跑同一套代码，验证角色无关性。
