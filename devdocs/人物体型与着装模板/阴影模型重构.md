## 1. 背景与目标

当前阴影由五套互不相干的规则拼成：源图亮度分位（`_tone_planes`）、发块 bbox 比例（`_hair_shadow`）、美术线宽常量（`rim_shadow`）、发际下移带（`hair_band`）、眼部锚定带（`fore/chin`）。每套都有自己的尺度与作用域，导致同一张脸上出现四种互相矛盾的暗面，窄发束被 20px 暗带吞掉，白衣阴影贴着线稿长成碎块。

**目标**：用一套可解释的模型替代五套规则——固定光向、按连通块的局部尺度取暗面、每个材质只允许一种作用域，并让所有阴影都能被同一组指标验证。

## 3. 统一阴影模型

### 3.1 光照

- 全角色只允许一个光向：`drawing.light = "upper-left"`（`schema.validate_drawing` 已强制）。
- 光源向量 `L = (-√2/2, -√2/2)`（图像坐标，x 向右、y 向下）。
- 受光侧判定：对平滑后的距离场取梯度 `g`（指向形状内部），外侧法线 `n = -g`；`n · L < 0` 即背光侧。
  实现上等价于 `gx·Lx + gy·Ly > 0`。

### 3.2 局部尺度（取代 bbox 常量）

对每个材质连通块：

1. `d = distance_transform_edt(mask)`（到轮廓的内距）；
2. 骨架 `skel = mask ∧ (d ≥ maximum_filter(d, 5))`；
3. 用 `distance_transform_edt(~skel, return_indices=True)` 把最近的骨架内距传播到每个像素，得到**局部内切半径** `R`；
4. 暗带宽度 = `ratio × R`，用 `d ≤ ratio × R` 取带。

性质：窄发束（R≈4–8）自动得到 1–3px 暗带；头冠/躯干（R≈25–60）得到 4–14px 大块面。**不再出现“按整张图/整块材质 bbox 算宽度”的常量**。

### 3.3 暗面语义（互斥、可嵌套）

| 层 | 定义 | 用途 |
|---|---|---|
| `mid` | `背光侧 ∧ d ≤ r_mid·R` | 材质主暗面（体积） |
| `deep` | `mid ∧ d ≤ r_deep·R` | 更深一档（同一背光侧，向内收） |
| `core` | `deep ∧ d ≤ r_core·R` | 仅头发/最深结构 |
| `cast` | 遮挡物沿 `-L` 方向平移 `depth` 后落到接收物上 | 刘海→脸、领→衣 |
| `occlusion` | 真实材质接缝向 `under` 侧收窄的带 | 领/裙/蝶结的层叠投影 |
| `highlight` | 头部区域内源图亮部（`lum≥0.74`）∧ 非线稿 | 头发受光面（跟随发束）、白衣亮面 |

所有层只允许落在所属材质内；层与层之间 `deep ⊆ mid`、`core ⊆ deep`。

### 3.4 线稿与边界

- 线稿（`lum < 0.22`）向外膨胀 2px 后作为“统计排除区”：亮度/高光统计不得把线稿抗锯齿当暗面。
- 轮廓带可以贴线稿（cel 画法本就如此），但**不得由内部线稿派生阴影**——这是问题 4 的结构性修复。

## 4. 各材质规则（重构后）

| 材质 | 参数 | 规则 |
|---|---|---|
| 头发 | `r_mid=0.75, r_deep=0.30, r_core=0.12` | 背光侧分档；取消 `_hair_shadow` 与水平截断；删除手绘弧线高光 `_hair_streaks`，高光改取头部区域（脸顶至眼线）内源图亮部（`lum≥0.74`）+ 连通块去噪 |
| 皮肤 | `r_face=0.55` | ① 刘海投影：hair 沿 `-L` 平移 4px 落到“脸部附近皮肤”；② 每个皮肤连通块背光侧窄带（**脸部块仅保留下 35% = 下巴/颌下区**，避免沿轮廓带被五官打碎、覆盖脸颊/眼周——v9.2 订正）；③ 颈部（独立连通块）顶缘 4px 投影；④ 删除 `low` 分位带与全宽 `fore` 带 |
| 白衣 | `r_mid=0.58, r_deep=0.26` | 只用轮廓几何，不用源图亮度；贴皮肤/头发 3px 内仍保持白色；deep 为 mid 内收带 |
| 布料 | `r_mid=0.50, r_deep=0.26` | form 分两档 tone（不再全 tone2）；颜色必须能吸附到色板；`skirt` refs 改为色板三色 |
| 蝶结/虹膜 | — | 保持 flat / 最近 ref，不参与体积分档 |
| 纽扣 | — | 采用“全无”策略：新模型不因内部线稿生成暗块，绿环消失；不为纽扣单开规则 |

### 4.1 遮挡带

- `layer_edge` 先对 `over` 做 1px 腐蚀得到“实心区”，再从实心区边界向 `under` 取带，宽度收窄：
  - collar→blouse：5 → 3
  - blouse→skirt：6 → 4
  - bow→collar：2 不变
- 目的：跳过蕾丝/锯齿的每个齿尖，避免 V 区被整片铺满。

### 4.2 分类空间先验

1. **孤立下半身发色岛**：hair 连通块若不属于最大发块、面积 <1200px、质心在下半身（>50% 身高），按邻域多数材质回收（问题 1）。
2. **发上白点**：白衣种子要求邻域 5×5 中 hair 占比 <50%；被头发包围的亮块归回 hair，并按高光上色（问题 4 的附属现象）。
3. **手/前臂保护**：沿用既有下半身暖白块回收。

### 6.1 附带修正：`white_purity` 统计口径

`lint.lint` 的 `pale = (minc > 200) & fg & (d_in >= 2)` 会把肤色基色 `#ffddcc`（chroma 51）算作“淡色”，导致该指标随露肤面积漂移：皮肤阴影变少 → 更多肤色基色进入统计 → 白衣纯度假性下降。现在增加 `chroma <= 40` 条件，只统计接近中性的亮像素，指标回到它本来要测的“白衣是否被染色”。

### v9.1（2026-11-23）—— 头发高光：删除手绘弧线，改取源图亮部

**问题**：momo 半身头顶出现横贯的白色斜线/横线光斑，与参考风格 `shinchou_02` 的干净 cel 高光不符。

**定位**（`_work/scratch/diag_hair_line.py`）：monkeypatch 捕获头发高光三个来源，头顶 827 个白色像素中 **718 来自 `_hair_streaks`**（6 条按 bbox 比例固定位置的硬编码弧线）、110 来自源图亮部、0 来自 `_hair_highlight` 回退。`_hair_streaks` 的弧线在当前头型下顶在头顶，形成突兀亮线。

**修复**（`tools/tachie/matregion.py`）：
- 删除 `_hair_streaks`（手绘斜线）与 `_hair_highlight`（水平回退带）两个函数及调用；
- 新增 `_keep_large_components(mask, min_px)` 连通块去噪辅助；
- 头发高光改取头部区域（脸顶至眼线）内源图亮度 `lum >= 0.74` 的像素，经 2×2 opening + 保留 ≥10px 连通块后涂 `hi_t`。

**阈值依据**：源图头发区亮度高度集中（p50=0.727, p90=0.745, p98=0.825），0.74 处是亮斑与普通色的悬崖——0.72 抓到 25.6%（整片亮面色，过量），0.74 抓到 3.28%（真正的画师高光，跟随发束纹理）。

**验证**：
- 视觉：v10 头顶斜杠消失，高光是跟随发束的分散小块（对比 `output/shadow_v9_half_x2.jpg` → `output/shadow_v10_half_x2.jpg`）；
- 度量：头发高光 748px = **3.28%**（目标 3–5%），分布在 76 行、单行最多 31px、**0 行超过总高光 15%**（无横贯带）；头发 base 49.8%（≥40%）；
- 回归：11 项 lint PASS；`tools/tachie` 42 tests OK。

### v9.2（2026-11-23）—— 脸部阴影去杂乱：脸块背光带限下巴区

**问题**：momo 半身脸部阴影杂乱无章——右脸颊、眼周、嘴周出现零碎暗块，不连贯，与参考 `shinchou_02` 集中在眼下横条 + 下巴投影的干净大块阴影不符。

**定位**（`_work/scratch/diag_face_shadow.py`）：monkeypatch 捕获脸部 mid 阴影三个来源，脸部 ROI 内 720px 阴影中 **642px（89%）来自 per-component band**（刘海投影 cast 仅 274px）。该 band 沿脸右轮廓（背光侧）全高分布，经过眼睛/嘴/鼻孔时被皮肤 mask 的缝隙**打断成 25 个碎段**，且覆盖了脸颊中部与眼周——这是杂乱的根因。

**修复**（`tools/tachie/matregion.py`，皮肤分支）：对被 `anchor["face"]` 覆盖的脸主块，`directional_bands` 产生的背光侧带只保留**最下 35%**（下巴/颌下区，`YY >= y_max - 0.35*H`），脸颊与眼周保持亮。其他皮肤块（四肢）不受影响。

**方向验证**（零成本预览，不改源码）：在诊断脚本里对比四方案——v10 原图（27.5%，杂乱）/ 下 50% band（22.3%，脸颊仍暗）/ 无 band（5.2%，太平）/ 下 35% band（16.8%，干净且下巴有立体感）。选定下 35%。

**验证**：

### v10.2（2026-11-24）—— 三处边界着色缺陷：根因与 v19 执行清单

**① 衣褶缝里的肉色（分类错误）**
- 位置：sprite (126,248) 33×39，后腰右侧衣褶；源图为白布折缝，真实手在其右侧。

- 修改：①宽度 ≤3px、两侧同材质、被墨线夹住的窄缝先归邻域材质再参与竞争；②`white_seed` 增加邻域投票（周围 ≥90% blouse 时禁止判 skin）；③「暖白归手」要求与白衣主体分离且位于身体外侧，排除衣内夹缝；④允许配置注入折缝保护（未实施：①–③ 已覆盖该形态，按需再加）。

**② 左胸发边灰带（投影模型错误）**
- 位置：sprite (42,141) 39×61，左胸与发梢交界。
- 根因：遮挡体取全部 hair；`cast_shadow` 仅按 `-light*8px` 平移剪影并与 `~source` 求交，永远产出贴边带；无接收面朝向门控，投影落在受光侧；tone 1 过浅；`white_edge` 再清掉接触处 3px，形成白缝与灰绿条纹。
- 参考经验（`refs/proportions` 02/08/14/18/19 五张）：均左上光；头影落在颈→锁骨→上胸/衣领，严格位于背光侧；范围与头宽同量级、随头身比缩放；接触最深、远端渐浅；高领/衬衫领形成「头→领→衣」分层投影链；不存在沿发梢的平行条带。
- 修改：①遮挡体改为 `shoulder_y` 以上头团（`body_guide` 已有 `head_top/head_x/shoulder_y`），并按头宽 ±0.5 裁剪；②深度由头宽/肩宽推导，废止 `W/32`；③背光半平面门控（`x ≥ center_x`，即躯干圆柱场的背光侧）；④分层投影链由现有配置遮挡（collar→blouse）承担，头层只投可见衣领/上胸，不重复投影；⑤接触 1px deep AO，外侧 mid 渐隐；⑥`white_edge` 不得清除 occlusion。
- 验收（否定断言优先）：左胸受光侧不出现任何投影色；头影仅出现在右下背光侧；投影范围与头宽同量级；接触带无白缝。

**③ 衣摆/裙交界的米色亮楔（场连续性错误）**
- 位置：sprite (142,283) 24×21。
- 根因：`cylindrical_field` 每行按断口拆成独立圆柱；衣服把裙子切成 `(40–96)(100–123)(148–167)` 三段，最后一段仅 20px，段中心 x≈158 被当成受光核，产生 base 米色亮楔；y=301 两段合并后亮楔消失。

**② 头影模型（`drawing.py`）**
- `_head_occluder()`（:589）：取 hair∪skin 中行号 `< shoulder_y` 的部分，头宽优先用 `skin.sum()>=50` 时的 skin bbox 宽，否则取头团质量宽×0.5；再按 `head_x ± 0.5×头宽`、`rows >= head_top` 裁剪。无 `shoulder_y`（未传 `body`）时返回 `None`，整段跳过。
- `_head_cast_depth()`（:632）：`clip(0.30×头宽 + 0.06×躯干宽, 4.0, 0.8×头宽)`，废止 `W/32`；momo 实测 35.97 px。
- 接收面门控：`back_lit = (xx >= center_x) & (yy >= shoulder_y − 1)`，投影源 `shading.cast_shadow(head, base, light, depth)`；`contact = binary_dilation(head, iterations=1) & base & back_lit` 作 1px 接触深化（tone 2），外侧 tone 1。
- `white_edge`（:899–:900）只清 `form`，不再清 `occlusion`，消除接触处白缝。
- 结果：momo 受光侧缺陷框（`[150:215, 40:82]`）遮挡像素 552 → 140，剩余 140 为 y202–214 的 collar→blouse 配置缝，非头影；`stats` 中两条 `derive=="head_cast"`（blouse 222 px、collar 319 px）。
- **已知边界**：momo 上 `contact_pixels == 0`。衣物与头团的首个接触点落在 x≈127–129（体轴处），被 `x >= center_x` 门控排除，且发丝与衣领本就相邻、无白缝。接触带机制由合成用例 `test_contact_band_touches_the_occluder_without_a_white_gap` 单独覆盖（断言 `distance_transform_edt(~head)[occl].min()==1.0` 与 tone 最大值 2）。

**① 折缝肉色（`matregion.py`）**
- `_absorb_ink_seams()`（:269）：横向+纵向扫描 1–3 px 连续 run，若两侧紧邻墨线（`dark | ((idx<0) & fg)`）且墨线外侧两侧同属某 white 材质、run 内含 skin，则并入该 white；`white_seed |= moved`。
- white_seed 之后新增 5×5 邻域投票：`blouse_frac >= 0.90` 的 skin 像素改判白。
- 「暖白归手」保留「下半身 + 外侧 + 暖色 + 有饱和」判据；**不得**再以「是否属于白衣主连通块」作为门控（v19 曾加、v20 已撤，见下）。
- `_absorb_enclosed_skin()`（:330）在函数末尾执行：`2<=area<=160`、`distance_transform_edt(comp).max()<=2.5`、外环 95% 以上为 white∪ink 的薄 skin 块归外环多数 white。
- 结果：区域 ① skin 88 → 0。**但当时「手/颈/手臂未变」的判断是错的**——两只手同时被涂白，见下条订正。
- **① 追加订正（v20）**：v19 曾给「暖白归手」加 `& ~main_white` 门控，结果**两只手被整体涂白**（sprite 左 (49,226)–(69,255) 363 px、右 (162,239)–(187,282) 698 px）。原因是手指与袖口/裙摆在同一 white 掩码里天然连通，`main_white` 对标为手部像素恒为真；门控对折缝并非必要——夹缝已由 `_absorb_ink_seams` / `_absorb_enclosed_skin` 按宽度与拓扑处理。已删除 `main_white` 计算与该门控（`matregion.py` 最后的 hands 规则），并补 momo 守卫：左手 skin ≥300、右手 ≥600、区域 ① skin == 0。订正后 skin 3922 → 4905（+983 恰为两只手），16 色 / midgray 0、1px 4442 / 2px 1017；产物 `output/shadow_v20_half.png`、`shadow_v20_hand_left_x8.png`、`shadow_v20_hand_right_x8.png`、`shadow_v20_waist_fold_x8.png`。最大场断口变为 0.0500（y=216 blouse→skirt，两侧同处 >0.35 中间带、无可见楔；③ 的衣摆断口 y≈297 为 0.0178）。

**③ 场连续性（`shading.py` + `drawing.py`）**
- `build_cloth_layers()` 先对「衣服并集」求一次 `body_field = cylindrical_field(base, light)`，各材质只做裁剪而非各自重算；cloth 组与 white 非主体用 `field_bands(body_field, …)`，主体 white 传 `field=body_field` 给 `_bust_form()`（:672，函数内 `np.array(..., dtype=float64)` 拷贝，避免污染共享场）。
- `cylindrical_field()`（:153）改为先收集全部行 run 再统一填场；`len(run)<=2 → 0.5`；`len(run)<12` 时用 `_nearest_long_run()`（:135，向上/下各搜 8 行）继承最近长段参数，找不到才自算。
- 新增指标 `_form_field_break()`（:660）：`_run_widths()`（:644）过滤出「两侧宽度差 ≤1 且宽度 ≥12」的材质断口，取两侧场差最大值。momo 实测 **0.0408 < 0.05**（初版 0.76 是把轮廓宽度变化误当断口）。
- 结果：v19 放大图中 v18 的米色亮楔消失，衣摆→裙过渡连续。

### v10.3（2026-11-25）—— 手部暖白回收补记（v21/v22）+ 虹膜/眼部高光色相收口（v23–v26）

本节补记 v21/v22（此前未入档）与 QA 问题 5 的完整归因、修复、验证。测试基线：`tools/tachie` 62 passed、`tools/common` 13 passed。产物：`output/shadow_v26_half.png` / `_half_white.png` / `_half_x2.jpg`。

**v21/v22：手部暖白回收（`matregion.classify_materials` 末尾 hands 规则）**
- 现象：v20 后两只手仍有部分像素被涂成白衣白/布灰，边缘呈碎块。
- 动作：在既有「暖白归手」逐像素规则（`lower`（y > 0.55 身高）+ `side`（距体轴 > 10% 宽）+ 暖色 `R-B>14` + `sat>0.07` + `lum<252`）之外，补一条连通块规则（`matregion.py:614–638`）：按白衣连通块遍历，**跳过白衣主体 `main_w`**，只把 40–2000 px、质心在下半身（>0.52 身高）、平均 `R-B>8` 占比 ≥0.55 的分离白块整体归 skin。`main_w` 只在这条连通块规则里用于跳过衣服主体；逐像素规则不以 `main_w` 作门控（v20 的教训见上）。
- 实测：v20→v21 有 359 px 由白/布灰转皮肤色（画布 x253–370、y158–288，双手区）；v21→v22 再 12 px（x313–335、y167–171）；`skin` 4905 → 5246（v22 计数；v26 口径见 §6）。
- 复现：用同一命令（`--tier half --palette characters/momo/palette.json --material-region`）渲染，与 `output/shadow_v22_half.png` 逐像素 diff = 0。

**v23/v24：色相漂移守卫（`matregion.render_spec.snap`，:825–:839）**
- 归因：`snap()` 纯 RGB 最近邻。虹膜第二档 `#1f5f5a`（暗青，hue 175°）到 taupe `(74,63,54)` 的 RGB 距离 4169，比到青绿槽 `(47,143,134)` 的 4496 **更近 0.7%** → 上虹膜被画成咖啡色；同一机制使领结暗金 `#a87a1e` 落到肤色深档 `(169,102,80)`（距离 2901）。
- 修复：`snap()` 增加**色相守卫**——参考色饱和度 ≥0.20 时，只在「色相差 ≤15° 且候选饱和度 ≥0.15」的槽位里取最近邻；无同色相候选才回落全局最近邻。低饱和（白/灰/黑）参考不受影响。

- 色板槽位未改动（16 色不变），只改量化映射。

**v25/v26：单眼白高光被吞（QA 问题 5，`matregion.py:498–:506`）**
- 归因（像素级）：
  1. `hair` 的 `refs[0]` 是 `#ffffff`，与 `blouse` 的纯白参考在分类距离上并列，`argmin` 取较小索引 → 眼内纯白高光初始被判为 **hair**（`raw` 实测）。
  2. 眼内高光救援规则要求：亮块（`sat<0.25 & lum>205`）面积 ≤ `eye_bright_max`，且 **1 px 环**的 `seed|dark_ring` 占比 ≥0.55。左眼高光被睫毛/JPEG 切碎成 15 px 块，1 px 环被其下方的 taupe 阴影稀释到 **0.42** → 救援失败；右眼 19 px 块为 0.56，刚好通过。
  3. 未获救援的块随后被 fragment absorption 判为孤立 hair 小块，按环多数并入 **collar** → 画成 taupe；同时虹膜上虹膜的暗青档已被 v23 守卫改青绿。结果：左眼「咖啡色 + 无白高光」，右眼正常，与用户描述完全一致。
- 修复：救援规则的环半径 1 → 2 px（阈值仍 0.55）。双眼实测占比：左 0.42 → **0.75**，右 0.56 → **0.75**。
